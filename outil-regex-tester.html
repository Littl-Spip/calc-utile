Ce qu'est une regex

Une expression régulière décrit un motif de texte : « trois chiffres suivis d'un espace », « une adresse e-mail valide », « tout ce qui se trouve entre deux balises ». C'est un langage compact, puissant, et notoirement difficile à relire — d'où l'intérêt d'un testeur qui montre immédiatement ce qui est capturé.

Un testeur affiche les correspondances, les groupes de capture et, souvent, le détail de chaque groupe. C'est le moyen le plus rapide de comprendre pourquoi une regex ne matche pas ce qu'on attend.

Les pièges classiques

Le plus fréquent : oublier que les métacaractères doivent être échappés (un point veut dire « n'importe quel caractère »). Ensuite, la gourmandise : .* avale tout jusqu'à la dernière occurrence, alors que .*? s'arrête à la première. Enfin, les ancres : sans ^ et $, une regex validant un code postal acceptera aussi « 75001abc ».

Faut-il valider un e-mail avec une regex ?

Non, pas sérieusement. La spécification des adresses e-mail est bien plus permissive qu'on ne le croit. Une regex stricte rejette des adresses valides ; une regex large accepte des adresses fausses. La seule validation fiable est l'envoi d'un message de confirmation.

Questions fréquentes

Quelle différence entre match et test ?

Selon le langage, match renvoie les correspondances trouvées, test renvoie seulement vrai ou faux. Pour vérifier un format, test suffit et coûte moins cher.

Les regex sont-elles lentes ?

Une regex mal construite peut exploser en temps de calcul (catastrophic backtracking) sur une entrée longue. Évite les quantificateurs imbriqués comme (a+)+.
