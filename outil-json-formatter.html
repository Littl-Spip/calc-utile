Formater du JSON : indenter, valider, comprendre

Pourquoi indenter

Le JSON est un format d'échange : il n'a pas besoin d'être lisible par un humain, seulement par une machine. Mais dès qu'on doit le corriger ou le lire, un fichier sur une seule ligne devient illisible. L'indentation ajoute des retours à la ligne et des espaces, sans changer la donnée.

Formater ne modifie pas le contenu : les valeurs, l'ordre des clés et les types restent identiques. C'est une opération sûre, à condition de ne pas laisser un formateur réécrire les nombres (certains arrondissent les décimales).

Les erreurs de syntaxe les plus fréquentes

Une virgule en trop après le dernier élément, un guillemet simple au lieu de guillemets doubles, une clé non entourée de guillemets, un commentaire (interdit en JSON), une valeur NaN ou undefined (interdites aussi). Le message d'erreur indique souvent la ligne et la position : commence toujours par là.

JSON et ses cousins

JSON5 autorise les commentaires et les virgules finales, YAML est plus lisible mais plus ambigu, et JSONL stocke un objet par ligne pour les gros volumes. Pour des données tabulaires, le CSV reste plus compact.

Questions fréquentes

Le formateur envoie-t-il mes données quelque part ?

Non, le formatage se fait dans ton navigateur. C'est important si le JSON contient des données internes.

Comment minifier du JSON ?

Supprime les espaces et retours à la ligne inutiles. La minification réduit la taille de 20 à 40 % sur un JSON indenté, ce qui compte pour une réponse d'API.
